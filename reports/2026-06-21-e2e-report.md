## 4. Known limitations / gaps

1. **Index types unreachable via the live API on small data (P1, Finding 4).** Declared index (HNSW/IVF-PQ/RaBitQ/SQ/…) builds only on **sealed** segments; seal threshold is hardcoded 512 MB with no seal/flush REST route, so any small dataset stays in the growing segment and is brute-forced as **Flat** regardless of declared type. Per-index correctness IS unit-tested in `veda-index`, but recall/latency cannot be compared or operated through the API. Needs a `POST /collections/{c}/seal` route and/or a `VEDA_SEAL_THRESHOLD` env.
2. **text→video embedding weakness (P2, Finding 2).** jina-v5-omni video↔text cosine distances cluster ~0.78–0.89 with low discrimination; a matching text query does not surface the matching video above unrelated media. text↔audio/text↔text are strong on the same pipeline to model/frame-sampling quality issue, not Veda.
3. **OCR engines down (env).** FlashParse / GLM-OCR not running; `process-document` not exercised. Corpus built directly from OmniDocBench annotations.
4. **SPLADE not configured.** No sparse encoder in env; `sparse_vector` queries return graceful empty results.
5. **MinIO SigV4 listing quirk.** Standalone bucket-list was inconclusive (cred-scoping on the gpu-host-d MinIO), but Veda's own S3 client wrote+read byte-exact — not a Veda defect (2.G #4).
6. **GAP-A: cost/cache/ttft histograms are lazy (P2).** Counters now pre-registered at 0 (fix `ea3292a`); histograms still only render after first record (acceptable — fire per run). `veda_insert_*` only fires on the non-log-primary insert branch.
7. **MVCC time-travel + txn write-write conflict** not demonstrable through the current REST surface (commit_ts None on embed-insert; no external-key upsert). Basic lifecycle confirmed.
8. **LLM-via-Veda 404 (P1, host-script env, Finding LLM-1).** Live regression this phase; LLM model is healthy. One-line host-script env fix + restart resolves it.
